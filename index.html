CR-Bench: Evaluating the Real-World Utility of AI Code Review Agents

Kristen Pereira*, Neelabh Sinha*, Rajat Ghosh, Debojyoti Dutta
Nutanix AI

Abstract

Code review remains one of the most difficult software engineering tasks to automate because it lacks a formal verification signal and contains significant subjectivity. We introduce CR-Bench, a benchmarking dataset derived from SWE-Bench designed to evaluate AI code review agents in realistic pull-request settings.

We also introduce CR-Evaluator, a fine-grained evaluation framework that measures not only bug detection accuracy but also developer-centric metrics such as usefulness and signal-to-noise ratio.

Motivation

Automating code review is challenging because:

  • Reviews can be subjective (style, refactoring, documentation)
  • Multiple valid review interpretations may exist
  • Many existing benchmarks rely on synthetic tasks

CR-Bench focuses specifically on objective defect detection in real open-source repositories.

CR-Bench Dataset

CR-Bench converts SWE-Bench issues into code review tasks that include complete pull-request context.

  • Full Pull Request context
  • Patch diff
  • Bug description
  • Taxonomy labels (category, impact, severity)

Figure 2: CR-Bench pipeline for transforming SWE-Bench issues into code review tasks and evaluating agents using CR-Evaluator.

Dataset Statistics

CR-Bench contains two dataset variants:

  • CR-Bench: 584 tasks
  • CR-Bench-Verified: 174 manually validated tasks

Figure 3: Distribution of bug category, impact, and severity across CR-Bench datasets.

CR-Evaluator

CR-Evaluator categorizes each generated review comment into:

  • Bug Hit — identifies the true defect
  • Valid Suggestion — useful but unrelated comment
  • Noise — incorrect or hallucinated comment

The system measures both traditional and developer-centric metrics:

  • Precision
  • Recall
  • F1 Score
  • Usefulness Rate
  • Signal-to-Noise Ratio (SNR)

Experiments

We evaluate two code review agents:

  • Single-shot agent — generates reviews in one pass
  • Reflexion agent — iteratively improves review suggestions

Results

Our experiments reveal a key trade-off between recall and signal quality.

Figure 4: Recall distribution across bug category, impact, and severity.

  • Reflexion improves recall but increases noise
  • Single-shot provides higher signal-to-noise ratio

Conclusion

CR-Bench provides a realistic benchmark for evaluating AI code review agents in production-scale software repositories.
